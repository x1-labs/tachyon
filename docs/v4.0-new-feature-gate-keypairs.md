# X1 v4.0 — New Feature-Gate Keypairs (minted, X1-controlled)

**Date:** 2026-07-08
**Context:** upgrading X1 Tachyon from upstream agave v3.1.14 → v4.0.3.

agave v4.0.3 introduced **25 new feature gates** (24 top-level + 1 nested) that did not exist in
v3.1.14. **21** had real upstream keypairs and have been minted + swapped to X1-controlled pubkeys
in `feature-set/src/lib.rs`; **4** carry non-activatable upstream vanity-stub ids and were left
unswapped (see Notes).

- **Keystore:** `~/Documents/x1-testnet/x1_feature_gate_keys/<feature>_<pubkey>.json` (one file per
  gate; the keypair's pubkey equals the code `declare_id!`).
- **All remain INACTIVE on X1.** Swapping an inactive gate's pubkey is consensus-neutral (no
  activation account exists under either key on any X1 chain).
- **To activate one** (per the `x1-feature-gates` runbook): roll the whole fleet onto the v4.0
  binary first, then `./target/release/x1 feature activate <keystore>/<feature>_<pubkey>.json
  testnet --url https://rpc.testnet.x1.xyz -k ~/.config/solana/id.json`, soak ≥2 epochs, then
  mainnet — one gate per epoch.

## Notes

- **Economic-policy gates (#10–#14, #20, and #2 via the cost-model move):** change X1 economics
  and interact with the CU×10 fee model. Human policy decisions — never routine promotions.
  - **SIMD-0437 chain (#10–#14):** hard dependency — `deprecate_rent_exemption_threshold`
    (SIMD-0194, X1 `CUVnURvdxMeFo3pZ22C5WpYGNXaAdgCZpfGyFuPBreEp`, **INACTIVE on X1**) must
    activate FIRST, then 6333 → 5080 → 2575 → 1322 → 696 strictly in descending order, one per
    epoch. Out-of-order activation *raises* rent. Same-epoch multi-activation picks the lowest.
  - **#20 VAT:** burns 1.6 XNT per epoch per vote account and caps Alpenglow vote accounts —
    needs X1-specific economic review before any Alpenglow adoption.
- **#17 `buffer`** is the **source buffer account address** for the core-BPF stake-program v5
  upgrade (`Bank::upgrade_core_bpf_program`), not an activation gate. Before activating #16, X1
  must deploy the v5 stake program bits to a buffer at this address using this keypair (mirrors
  v3.1's `vote_state_v4::stake_program_buffer` treatment).
- **NEVER activate** (standing list, from the v4.0 gate-A audit):
  - `zk_token_sdk_enabled` (X1 `43XuaFmpSgY6mejuttRGhXc8FsuUQxFZdBMG95bhv17M`) — v4.0 gutted the
    zk-token-proof program to a 0-CU no-op; activating would enable a program that "verifies"
    every proof.
  - `reward_full_priority_fee` (X1 `2XpLmpsc…`) — would end the legacy 50%-burn fee distribution
    (XLT-100 keeps it live while inactive). Upstream deleted its runtime read in v4.0; X1's port
    re-gates the legacy path on it.
  - Old upstream keys of in-span-rekeyed gates: `6f2qai82…` (account_data_direct_mapping),
    `BUwGLeF3…` (enable_sbpf_v3_deployment_and_execution), `zkesAyFB…`
    (reenable_zk_elgamal_proof_program), `G6ANXD6p…` (stake_minimum_delegation_for_rewards), plus
    the v3.1-era `CxeBn9…`/`ENTRYn…` — v4.0 binaries do not recognize them.
- **X1-only gates preserved (7):** `enable_native_mint_wrap_account` (ACTIVE mb+tn),
  `validate_fee_vote_transaction_instructions` (ACTIVE mb+tn — consensus-load-bearing),
  `enforce_minimum_transaction_fee` (ACTIVE tn), `require_vote_submission_for_fee_exemption`
  (ACTIVE tn), `vote_min_stake_{1,10,100}_xnt` (inactive).
